<p class="lede">Fornax lets you call open-weight models as plain Java methods, <em>on your GPU, inside your JVM</em>.</p>

{/* snippet: Index#chat */}
```java
import org.liberationdata.fornax.llama.LlamaModel;
import org.liberationdata.fornax.llama.LlamaModel.Message;
import org.liberationdata.fornax.llama.LlamaModel.Options;

import java.util.List;

try (var llm = new LlamaModel("Qwen3-4B-Instruct-2507-Q4_K_M.gguf")) {   // weights load onto the GPU once
    llm.chat(List.of(Message.user("Name a country song about a robot.")), Options.DEFAULT, System.out::print);
}
```

That is a language model running in your own process. There is no Python, no model server, no HTTP and no second
process. The weights stay loaded between calls, and tokens stream back to a Java callback as they are produced.

## What you get

Fornax binds the C and C++ inference engines that the open-model world already runs on. They are the same engines
behind the popular command-line tools and servers, so you get their speed and their model support.

| Module | Engine | What it runs |
|---|---|---|
| `fornax-llama` | [llama.cpp](https://github.com/ggml-org/llama.cpp) | any GGUF language model (Qwen, Llama, Gemma, Mistral, ...), with chat, streaming, tool calls and JSON schemas; embeddings and reranking (Qwen3-Embedding, EmbeddingGemma 2, Qwen3-Reranker) |
| `fornax-tts` | llama.cpp (`mtmd`) | text to speech: Kokoro, ZONOS3, LFM3-Audio, Chatterbox, VoxCPM2, Qwen3-TTS, ... |
| `fornax-sd` | [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) | images and video: FLUX.1 and FLUX.2, Qwen-Image and Qwen-Image-Edit, SD 1.x/2.x/XL/3, Wan, LTX |
| `fornax-acestep` | [acestep.cpp](https://github.com/ServeurpersoCom/acestep.cpp) | ACE-Step 1.5 songs, with vocals and lyrics, up to several minutes |
| `fornax-yue2` | [yue2.cpp](https://github.com/ServeurpersoCom/yue2.cpp) | YuE2 songs |
| `fornax-whisper` | [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | speech to text with word timings: Whisper large-v3-turbo, base.en, any ggml Whisper model |
| `fornax-demucs` | [stems.cpp](https://github.com/betweentwomidnights/stems.cpp) | stem separation: vocals and backing, or drums, bass, other and vocals, with HTDemucs v4 |
| `fornax-core` | | what the others share: native loading, `ModelPool`, `HfCache`, `Audio`, `Vectors` |

Every model class is `AutoCloseable`, and its weights are freed on `close()`. A model can be called from any thread;
its calls run one at a time. From virtual threads, use the `...Async` methods, which run the native call on the
model's own thread (see [Threading](/docs/guides/threading/)). A [`ModelPool`](/docs/guides/model-pool/) keeps
several models loaded and gives each one user at a time.

## How it works

Fornax calls the engines through Java's **Foreign Function & Memory API** (Java 22 or newer; Kiln 0.1.0 itself
needs 25). A Fornax call is a native function call, made directly from your thread, or from the model's own thread
for the async methods.

Each engine is built into **one self-contained shared library**, with its own copy of ggml (the tensor library
under all the engines) linked in statically and kept private. The engines pin different ggml versions, so this is
what lets several of them share one process: an LLM, a diffusion model and a song model can all be loaded in the same
JVM at once.

How each module binds its engine depends on what the engine offers:

- `stable-diffusion.cpp` has a key/value C API, so `fornax-sd` binds it directly. Any option the engine documents can
  be passed through.
- `llama.cpp` has a C API too, but it passes structs by value and is moving to a new batch API, so `fornax-llama`
  binds a small, stable C layer instead. `fornax-tts` is one more such layer, over llama.cpp's audio generation.
- `acestep.cpp` and `yue2.cpp` are C++ only, so each gets a layer of about 100 lines: a JSON request in, PCM audio
  out.
- `whisper.cpp` has a C API, but it passes two large parameter structs by value, so `fornax-whisper` binds a small C
  layer that takes plain arguments and reads the results back token by token.
- `stems.cpp` has a C ABI of size-tagged structs in a function table, so `fornax-demucs` binds a small C layer over it:
  planar audio in, planar stems out.

Give an engine a catalogue name (`qwen3-4b`) or a Hugging Face reference (`unsloth/Qwen3-4B-Instruct-2507-GGUF:Q4_K_M`)
and Fornax downloads it into the Hugging Face cache on first use. Or fetch weights ahead of time with `fornax pull` or
the Hugging Face CLI, or pass file paths directly: a path never downloads anything.

## Status

Fornax is early. Everything below runs from Java on Linux with an AMD Radeon 8060S (Ryzen AI Max+ 395 "Strix Halo",
128 GB unified memory) using the **Vulkan** backend:

| Model | Result |
|---|---|
| Qwen3 4B Instruct (Q4_K_M) | ~75 tokens/s, streamed through a Java callback: as fast as llama.cpp's own `llama-bench` |
| Qwen3-Embedding 0.6B (Q8_0) | ~420 embeddings/s (20-token passages, 256 to a batch), matching `llama-embedding`'s vectors (cosine 1.000000) |
| ACE-Step 1.5 XL turbo | a 3 min 20 s song in 57 s |
| ACE-Step 1.5 turbo | a 60 s song in ~15 s |
| YuE2 3B (Q8_0) | a 60 s song in ~60 s |
| FLUX.2 [klein] base 4B (fp8) | 768×768, 12 steps in ~130 s |
| Qwen-Image 2512 (fp8) | 1024×1024, 20 steps in ~13 min |
| Whisper large-v3-turbo (q5_0) | 55 s of speech in 1.8 s (31× real time), with DTW word timings |
| HTDemucs v4 (F32) | a 3 min 9 s song split into four stems in 26 s (7.3 s of audio per second) |

[Benchmarks](/docs/benchmarks/) sets these against each engine's own tool and against ComfyUI, with the command behind
every figure.

## Supported backends

You choose a GPU backend when you build the native libraries; the Java code is the same for every backend.

| Backend | GPUs | State |
|---|---|---|
| Vulkan | AMD, Intel, NVIDIA | what Fornax is tested on |
| HIP (ROCm) | AMD | passes the test suite on the 8060S (one rerank score drifts: [#80](https://github.com/liberation-data/fornax/issues/80)); runs LTX video faster than Vulkan |
| CUDA | NVIDIA | builds from the same script; not tested yet |
| Metal | Apple silicon | passes the test suite on an M2 Max; songs and video not run yet |
| CPU | any | no GPU; slow, but useful to check a setup |

[Choosing a GPU backend](/docs/guides/gpu-backends/) covers each one and the settings that matter. Reports and fixes
for the untested ones are welcome.
